# Параллельное умножение матриц (ОС, Python)

Учебный проект по операционным системам: умножение матриц с использованием нескольких процессов Python, синхронизация общих счётчиков, обмен данными между процессами и сравнение способов распределения вычислительной работы.

В репозитории представлены реализации требований на оценку **3** и **4**.

## Возможности проекта

### Оценка 3 — параллельное умножение обычных матриц

- Генерация матриц со случайными целыми числами.
- Умножение матриц `A (M × K)` и `B (K × N)`.
- Последовательная реализация для проверки результата.
- Параллельное вычисление с помощью `multiprocessing.Process`.
- Статическое распределение непрерывных блоков строк между процессами.
- Общий счётчик выполненных строк на `multiprocessing.Value` с блокировкой.
- Передача готовых строк в главный процесс через `multiprocessing.Queue`.
- Проверка совпадения последовательного и параллельного результатов.
- Измерение времени, ускорения и эффективности.
- Сравнение порядка циклов `i → j → t` и `i → t → j`.

### Оценка 4 — IPC, нижнетреугольная матрица и два способа распределения

- Генерация матриц в отдельном дочернем процессе.
- Передача матриц генератором главному процессу через `multiprocessing.Queue` (IPC).
- Хранение нижнетреугольной матрицы `A` без нулей выше главной диагонали: строка с индексом `i` содержит `i + 1` элементов.
- Умножение `A (N × N)` на обычную матрицу `B (N × K)`.
- Статическое распределение (`static`): каждый процесс заранее получает непрерывный диапазон строк.
- Динамическое распределение (`dynamic`): процессы получают следующую свободную строку из общего счётчика, защищённого блокировкой.
- Сборка результирующей матрицы в главном процессе по индексам строк.
- Отображение прогресса и проверка совпадения с последовательным результатом.
- Сравнение времени IPC, последовательного и параллельного умножения.

> **Важно:** в Python-реализации используются процессы ОС (`multiprocessing.Process`), а не потоки `threading.Thread`. Это позволяет выполнять CPU-bound вычисления в нескольких процессах независимо от GIL CPython. При передаче матриц рабочим процессам учитываются расходы сериализации и копирования данных.

## Требования

- Python 3.10 или новее (проект разрабатывался и проверялся на Python 3.13).
- `matplotlib` — построение графиков при запуске бенчмарков.

Установка зависимости:

```bash
python -m pip install matplotlib
```

В Windows рекомендуется запускать скрипты из обычного терминала PowerShell или CMD на основной ОС, а не внутри виртуальной машины, если цель — измерить производительность физического компьютера.

## Запуск задания на оценку 3

Формат аргументов:

```bash
python grade3.py M K N T
```

- `M` — число строк матрицы `A`;
- `K` — число столбцов `A` и строк матрицы `B`;
- `N` — число столбцов матрицы `B`;
- `T` — количество рабочих процессов.

Пример:

```bash
python grade3.py 800 800 800 6
```

Запуск автоматического тестирования:

```bash
python grade3.py --benchmark
```

Бенчмарк выполняет несколько повторов для размеров матриц `300`, `450`, `600`, `800`, проверяет разные количества процессов, сравнивает результаты с последовательным умножением и сохраняет таблицы и графики.

## Запуск задания на оценку 4

Формат аргументов:

```bash
python grade4.py N K T static
```

или

```bash
python grade4.py N K T dynamic
```

- `N` — размер квадратной нижнетреугольной матрицы `A` и число строк матрицы `B`;
- `K` — число столбцов матрицы `B`;
- `T` — количество рабочих процессов;
- `static` или `dynamic` — способ распределения строк.

Примеры:

```bash
python grade4.py 800 800 6 static
python grade4.py 800 800 6 dynamic
```

Запуск автоматического сравнения:

```bash
python grade4.py --benchmark
```

В режиме бенчмарка используются размеры `300`, `450`, `600`, `800`, количества процессов от `1` до `12`, а также `24` и `48`; для каждой комбинации выполняется 5 повторов. Измерения обрабатываются усечённым средним: минимальное и максимальное значения отбрасываются, остальные усредняются.

## Как устроена реализация

### Межпроцессное взаимодействие (IPC)

В задании на оценку 4 функция `generate_matrices_ipc()` запускает отдельный процесс-генератор `_generator_worker()`. Генератор создаёт матрицы `A` и `B`, затем отправляет их главному процессу через `multiprocessing.Queue`. Сообщения содержат статус и данные матрицы. Главный процесс получает сообщения через `get()` и проверяет завершение генератора.

### Нижнетреугольная матрица

В матрице `A` нулевые элементы выше главной диагонали не хранятся. Например, матрица

```text
2 0 0
4 5 0
1 6 3
```

представляется в Python как:

```python
A = [[2], [4, 5], [1, 6, 3]]
```

Поэтому строки имеют разную длину и разную вычислительную трудоёмкость.

### Статическое и динамическое распределение

- **Static:** диапазон строк назначается процессу до начала вычисления. Деление выполняется с учётом остатка, чтобы все строки были распределены.
- **Dynamic:** процессы совместно используют `multiprocessing.Value` с блокировкой. Каждый процесс атомарно получает очередной индекс строки, увеличивает счётчик и вычисляет строку без удержания блокировки.

Готовые строки отправляются в очередь. Главный процесс записывает каждую строку в `C` по её индексу, поэтому порядок прихода сообщений не влияет на порядок строк в результате.

## Метрики

Для сравнения вычислений используются:

- **Ускорение:** `S(T) = t_sequential / t_parallel`.
- **Эффективность:** `E(T) = S(T) / T`.
- **Время IPC:** время генерации матриц отдельным процессом и их передачи через очередь (для задания на оценку 4).

`S(T) > 1` означает, что параллельный вариант быстрее последовательного. Значение эффективности показывает, насколько эффективно используется выделенное количество процессов.

## Проверка корректности

В обеих реализациях параллельный результат сравнивается с результатом последовательного умножения. Если матрицы различаются, программа сообщает об ошибке. В оценке 4 дополнительно проверяется корректность передачи матриц через IPC.

## Особенности интерпретации результатов

Параллельный вариант не обязан быть быстрее последовательного для маленьких матриц. Запуск процессов, передача аргументов, сериализация объектов, синхронизация и сборка результата создают накладные расходы. Динамическое распределение может лучше балансировать неодинаковую трудоёмкость строк нижнетреугольной матрицы, но получение каждой новой строки также требует синхронизации.

Результаты зависят от процессора, объёма памяти, ОС, фоновой нагрузки и размера матриц. Поэтому CSV-файлы и графики следует рассматривать вместе с описанием аппаратной и программной среды.
